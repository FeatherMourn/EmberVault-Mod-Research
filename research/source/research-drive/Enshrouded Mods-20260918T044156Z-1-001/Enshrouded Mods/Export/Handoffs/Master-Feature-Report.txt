# Architect Toolkit — Master Feature Report

## 1. Overall vision

Architect Toolkit is intended to become more than a shape generator. The end goal is essentially an **Enshrouded creative building suite + administrator toolbox + quality-of-life runtime**, while still allowing the user to preserve normal progression.

The main philosophy we settled on was **Creative With Progression**:

| Preserve normal gameplay  | Give creative/admin convenience |
| ------------------------- | ------------------------------- |
| Quests                    | Building materials              |
| Exploration               | Procedural construction         |
| NPC discovery             | Furniture/decor placement       |
| Flame progression         | Building tools                  |
| Bosses                    | Terrain editing                 |
| Skill progression         | Copy/paste and transformation   |
| Equipment progression     | Blueprint tools                 |
| World barriers by default | Optional admin bypasses         |
| Protected quest zones     | Optional admin utilities        |

So this is not supposed to become “everything unlocked and god mode all the time.” Those capabilities can exist, but they should be **optional administrator toggles**, separate from the normal Architect building experience.

# 2. Architect's Wand

The Wand is the central interaction tool.

### Current proven design

The stable base is the normal weapon:

**Weapon_T1_1H_Wand_01_Fire**

Item ID:

`1693828837`

It currently inherits the visible name **Crackling Wand** because custom localization is not solved yet.

We learned that making the Wand a vanilla `BuildTool`, Quickbuilder, or Construction Hammer causes Enshrouded to normalize it into those existing tool families. Therefore the Wand stays a normal weapon item.

The architecture is:

```text
Architect Wand
      ↓
Architect Runtime
      ↓
F8 Builder UI
      ↓
Procedural / native backend
      ↓
Preview and placement
```

Eventually we discussed having **tiers of Architect Wand**, so progression could unlock stronger construction functionality without abandoning the normal game progression model.

# 3. F8 Architect Builder UI

The custom F8 UI is intended to be the main construction interface.

### Already working

F8 currently:

* opens the Architect Toolkit menu
* releases the game's mouse capture
* displays a usable cursor
* stops player/camera input while the menu owns focus
* allows clickable controls
* closes with F8 or Esc
* restores game input afterward

Current sections are:

| Section   | Purpose                                        |
| --------- | ---------------------------------------------- |
| Shapes    | Procedural geometry                            |
| Structure | Walls, roads, stairs, arrays, etc.             |
| Terrain   | Terrain sculpting/replacement                  |
| Utility   | Copy/paste, measurement, admin utilities, etc. |

Current controls include Shape, Size, Mode, Material, Preview, and Place.

Longer term, the F8 UI should become contextual: the options shown should depend on which Architect tool/mode is selected.

# 5. Procedural geometric tools

These are the six shapes we have actually proven through the current safe EML backend:

| Shape              | Status |
| ------------------ | ------ |
| Hollow Square 4m   | PROVEN |
| Filled Circle 4m   | PROVEN |
| Ring 4m            | PROVEN |
| Sphere 2m          | PROVEN |
| Filled Cylinder 2m | PROVEN |
| Hollow Cube 2m     | PROVEN |

The backend currently has an EML allocator limitation: compressed placement data larger than **8 bytes** can trigger `No allocator set in BaseDynamicArray`.

That limits our current safe Lua-generated objects, but it does **not** represent the intended final limit of Architect Toolkit. The native layer gives us a route toward larger structures later.

# 6. Full Architect construction toolset

The larger toolset we planned goes considerably beyond those six shapes.

### Basic construction

# 29. Runtime/admin safety system

The runtime should eventually have a proper compatibility page.

Every dangerous native feature should follow roughly:

```text
Game build fingerprint
        ↓
signature scan
        ↓
sanity validation
        ↓
install feature
        ↓
monitor
        ↓
restore on unload
```

The toolkit should show whether individual systems are:

**Compatible**, **Disabled**, **Experimental**, or **Signature mismatch**.

That becomes especially important for:

* flight hooks
* teleport
* placement hooks
* freecam
* player-stat modification
* terrain operations

# 30. Current implementation status

There is a major distinction between the **vision** and what already works.

### PROVEN

Architect Wand remains a normal usable weapon wand.

Six procedural shapes work.

Custom placement data works.

Custom ghost/preview voxel models work.

F8 runtime UI works.

Mouse/input ownership works.

UI → JSON bridge works.

EML backend manifest works.

Selecting shapes maps to the correct real backend Item IDs.

Original native DLL injection works.

Commands reach native code inside `enshrouded.exe`.

The native `BuildingPlaceEvent` hook works.

The event exposes the blueprint `trackingItemId`.

Architect blueprint IDs have been observed passing through the real placement pipeline.

### EXPERIMENTAL

**v0.7 Armed Native Placement**

The intended path is:

```text
F8
→ choose Architect shape
→ Place
→ arm Item ID

next legitimate hammer placement
→ capture valid game placement context
→ substitute Architect Item ID
→ forward event
→ disarm
```

We have **not yet declared this successful** until the resulting structure is confirmed to actually become the selected Architect blueprint.

### UNSOLVED / FUTURE

Large arbitrary procedural blueprints.

Direct Architect placement without hammer trigger.

Direct native ghost preview.

Custom Wand localization.

Large-scale terrain editing.

Undo/redo.

Copy/paste.

Flight.

Teleport.

Freecam.

Item/stat admin UI.

Most of the administrator systems listed above.

## The eventual Toolkit in one picture

The complete vision is roughly:

```text
                 ARCHITECT TOOLKIT
                        │
        ┌───────────────┴────────────────┐
        │                                │
     F8 BUILD                         F7 TOOLKIT
        │                                │
  Architect Wand                    Admin / Config
        │                                │
 ┌──────┼─────────┐             ┌────────┼─────────┐
 │      │         │             │        │         │
Shapes Structure Terrain      Player   World    Movement
 │      │         │             │        │         │
Sphere Walls    Sculpt       Stats    Zones     Flight
Circle Roads    Paint        Items    Travel    Freecam
Dome   Stairs   Replace      Skills   Map       Speed
Arch   Bridge   Flatten      Craft    Altar     Autorun
 │
Selection / Transform
 │
Copy • Paste • Move • Rotate
Mirror • Arrays • Symmetry
 │
Blueprint Library
 │
Preview → Validate → Place
 │
Undo / Redo
```

So yes — **Architect Toolkit was always intended to become much larger than a geometry mod**. The shapes are really just the first proof that we can take control of Enshrouded's building pipeline. The end product we envisioned is closer to a combined **advanced builder, world editor, creative-mode layer, administrator console, movement toolkit, blueprint system, and developer inspector**, with everything modular enough that someone who wants normal progression can leave the cheat/admin features disabled.

One important caveat: from the Nexus/mod material currently available in this Project, I can specifically verify **Ember** and **Shroudtopia Glider Flight** as references. If we discussed additional Nexus mods in an older conversation that isn't represented in the current Project materials, I don't want to invent their names or features.
