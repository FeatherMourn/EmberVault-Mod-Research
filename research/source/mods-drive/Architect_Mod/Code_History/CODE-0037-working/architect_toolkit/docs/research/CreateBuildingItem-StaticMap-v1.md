# CreateBuildingItemAction Static Map v1

## Scope

Offline-only analysis of the supported Enshrouded revision 1076226 executable
(`AF2F5A1227911D8AA06B3908D6BD0211838211CAE14EA91099CB57D0DF990781`). The
analysis uses the on-disk PE, `.pdata` unwind boundaries, and decoded x64
instructions. It does not attach to the game, scan process memory, install a
detour, or write any game state.

Machine-readable output is generated by
`tools/SemanticActionObserver/scan_create_building_item_static.py`:
`bridge/create_building_item_static_map.json`.

This proves that the placement function eventually resolves an Item-ID keyed
record and forwards its first dword as `BuildingPlaceEvent.trackingItemId`.
It does **not** prove that `R8D` originated from `CreateBuildingItemAction`,
nor that the action payload reaches this function.

## Candidate scan and rejection

The scanner found 96 functions with generic accesses to offsets `+0x00`,
`+0x04`, and `+0x08` from one base register. These are shape matches only;
the same pattern is common in unrelated records, serializers, and dispatch
helpers. Each candidate is marked `UNRESOLVED_GENERIC_SHAPE` and includes its
function boundary, unwind RVA, field-access instructions, and direct call
targets in the JSON map.

No candidate has all of:

1. a uniquely identified action pointer and calling convention;
2. complete-field data flow from the reflected action;
3. a consumed-version read/update tied to that action; and
4. a validated edge into the proven placement chain.

Therefore:

```text
CreateBuildingItemAction native consumer: UNSOLVED
CreateBuildingItemAction live observation: NOT ENABLED
candidate consumed version: UNKNOWN
UiCreateBuildingItemEvent role: UNSOLVED
observer hook eligibility: false / fail closed
```

No build-profile RVA or signature was added for an unvalidated site. Existing
inventory and `BuildingPlaceEvent` functionality remain unchanged.

## Analyzer and correlation support

`SemanticCaptureAnalyzer` accepts future JSONL records with
`observer=create_building_item_action`. It reports raw version, selected index,
Item ID, offline DataIndex name resolution, candidate consumed-version data,
nearest placement, timing, thread relationship, and item-ID equality. A nearby
match is deliberately reported as `INSUFFICIENT_EVIDENCE`; it is never treated
as causal until a safe native consumer and lifecycle are proven.

## First unresolved boundary

The first unresolved boundary is the action-specific native dispatch/consumer
between reflected PlayerInput storage and the placement function's `R8D`
argument. The next safe step is a narrower static data-flow recovery from a
validated dispatch edge, not a generic offset hook. Until then, no live test can
produce action records from the current runtime.
