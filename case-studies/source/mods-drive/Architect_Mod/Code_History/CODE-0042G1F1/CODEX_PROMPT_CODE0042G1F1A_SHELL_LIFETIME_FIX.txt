B. FIX CLEAR-ADMIN-CONTENT PRUNING

Current logic is wrong because it removes only non-SHELL bindings whose Control exists and is not disposed.

That leaves stale entries when:
- PAGE control is disposed;
- PAGE control is null;
- SHELL control is disposed.

Implement deterministic pruning with this semantic order:

For every active binding:
1. Determine whether the bound object is still live.
2. If the object is missing/null -> remove it.
3. If it exposes an `IsDisposed` property and `IsDisposed == true` -> remove it.
4. If it is live and `LifetimeScope != "SHELL"` -> remove it.
5. Preserve only live `SHELL` bindings.

IMPORTANT:
Some shell event sources (for example `System.Windows.Forms.Timer`) may not expose `IsDisposed` the same way as `Control`.
Do not blindly dereference `.IsDisposed` for every object.

Use property-safe logic, e.g. inspect:
`$binding.Control.PSObject.Properties['IsDisposed']`
before reading the property.

Then rebuild `$script:adminActionControls` from surviving active bindings only:
- only entries with nonempty ActionId;
- only live surviving controls/components appropriate for action controls;
- do not retain stale page controls.
