ONE SOURCE DEFECT REMAINS

`Bind-AdminActionControl` still references `$EventId`, `$EventName`, and `$Operation` even though these are not parameters.

It currently works only because PowerShell resolves them from the calling `Register-AdminActionEvent` scope.

REMOVE THIS DYNAMIC-SCOPE DEPENDENCY.

Preferred implementation:

1. In `Register-AdminActionEvent`, explicitly call:

   Register-F7EventDefinition
     -EventId $EventId
     -Page $Page
     -Classification "ACTION"
     -ActionId $ActionId
     -EventName $EventName
     -Operation $Operation

2. If the definition is ambiguous/conflicting:
   - disable the control;
   - expose the ambiguity reason;
   - return false.

3. Change `Bind-AdminActionControl` so every identity value it uses is explicit.
   Recommended parameters:
   - Control
   - ActionId
   - EventId
   - Page
   - AllowDisabled

   It should NOT reference `$EventName` or `$Operation` at all if stable definition registration happens in the caller.

4. `Bind-AdminActionControl` should:
   - resolve the canonical action;
   - set the control Tag/accessible metadata with explicit EventId/ActionId/Page;
   - refresh `$script:f7ActiveBindings[$EventId]`;
   - refresh `$script:adminActionControls[$ActionId]` from active bindings;
   - enforce disabled/unavailable action state;
   - never use caller-scope variables.

5. `Register-F7UiEvent` should remain explicit and EventId-driven.
