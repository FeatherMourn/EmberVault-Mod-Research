GOAL

Fix the shared F7 event-inventory lifecycle so the already-migrated Home page remains stable across repeated rerenders and future page migrations can use a trustworthy denominator.

CURRENT PROBLEM

`Register-AdminActionEvent` and `Register-F7UiEvent` require EventId, but `$script:f7EventInventory` still stores strong WinForms Control references and appends rows on every render.

`$script:adminActionControls` also stores live controls by ActionId.

`Clear-AdminContent` clears visual controls only.

`Get-F7ActionBindingAudit` currently hard-codes:
    staleOrDisposedActiveBindings = 0

Therefore repeated Home renders can produce duplicate EventIds and retained/disposed controls.

REQUIRED ARCHITECTURE

Use two distinct layers.

1. Stable event-definition inventory

Keyed by mandatory EventId.

Definition metadata should include at least:
- EventId
- Page
- Classification: ACTION or UI_ONLY
- ActionId for ACTION
- EventName
- Operation

The stable definition inventory MUST NOT use a live Control reference as its identity or denominator.

Registering the same EventId again with the same definition must NOT append a duplicate definition.

If the same EventId is registered with conflicting classification/action/page semantics, fail closed and expose the ambiguity in the audit.

2. Active render binding map

Keyed by EventId.

Contains live render state such as:
- current Control reference
- Page
- ActionId if applicable
- render generation or equivalent current-render identity

Re-registering the same EventId during a rerender should replace/refresh the active binding for that EventId.

Active bindings from an outgoing page/render must be removed deterministically during Clear-AdminContent or page transition.

Do not use historical active Control references as the project-wide event denominator.

ADMIN ACTION CONTROL MAP

If `$script:adminActionControls` remains necessary:
- prevent stale control accumulation;
- update/remove entries on page clear/rerender;
- do not let old disposed controls remain as active bindings.

Do not weaken `Bind-AdminActionControl` capability gating.

AUDIT

Update `Get-F7ActionBindingAudit` so:

- totalEventDefinitions is derived from stable EventId definitions.
- duplicateEventIds represents actual conflicting/duplicate stable definitions, not normal rerender.
- activeBindings reports current active EventId bindings.
- staleOrDisposedActiveBindings is COMPUTED from current active controls using disposal/handle/liveness checks appropriate for WinForms; do not hard-code zero.
- ambiguousBindings uses EventId / stable identity, not Control.Name as its primary key.
- existing direct-event metrics continue working.
