GOAL

Add correct lifetime semantics for persistent F7 shell controls, then migrate all clearly UI-only shell events into `Register-F7UiEvent`.

After this pass:
- persistent shell event definitions/bindings survive page navigation correctly;
- page-owned active bindings are still cleared on `Clear-AdminContent`;
- all seven clearly UI-only shell registration sites use the explicit F7 event system;
- the AOB Scanner click remains the ONE intentionally-unmigrated shell ACTION for the next slice.

CURRENT LIFECYCLE PROBLEM

Current:
- `$script:f7EventDefinitions` is stable metadata keyed by EventId.
- `$script:f7ActiveBindings` is live state keyed by EventId.
- `Clear-AdminContent` currently resets ALL active bindings and ALL action-control references.

That is correct for PAGE controls but wrong for persistent shell controls.

A shell control such as navigation, admin form KeyDown, or bounds timer remains alive across page transitions. If its binding is placed in the same active map and then globally cleared, the audit becomes false even though the event handler still exists.

REQUIRED LIFETIME MODEL

Add an explicit lifetime/scope concept to the F7 event lifecycle.

Recommended vocabulary:

- `PAGE`
- `SHELL`

Use one stable field name consistently, e.g. `LifetimeScope`.

Apply it to:

1. Stable event definitions
   - EventId
   - Page
   - Classification
   - ActionId
   - EventName
   - Operation
   - LifetimeScope

2. Active bindings
   - Control
   - ActionId
   - Page
   - LifetimeScope

3. `Register-F7EventDefinition`
   - accept `LifetimeScope`
   - include it in conflict comparison
   - default to `PAGE`

4. `Register-F7UiEvent`
   - accept `LifetimeScope`
   - default to `PAGE`

5. `Register-AdminActionEvent`
   - accept `LifetimeScope`
   - default to `PAGE`
   - pass it through to definition/binding logic

6. `Bind-AdminActionControl`
   - accept/store `LifetimeScope`
   - default to `PAGE`

CLEAR-ADMIN-CONTENT BEHAVIOR

Change `Clear-AdminContent` so it removes only PAGE active bindings.

It must preserve active bindings where `LifetimeScope == "SHELL"`.

Then rebuild/recompute `$script:adminActionControls` from the surviving active ACTION bindings rather than blindly resetting it to an empty map.

Even though this pass will not yet add a shell ACTION, implement this correctly now so the scanner slice can use the same architecture.

Do not preserve disposed controls. If a preserved SHELL control is already disposed, drop it.
