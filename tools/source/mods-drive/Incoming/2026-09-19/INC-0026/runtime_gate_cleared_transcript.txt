**Fail-Closed State Handling (`PATCH_RECOVERY_REQUIRED`)**
- If a write fails or exact bit-for-bit `patchBytes` readback fails *after* copying the `savedOriginalBytes`, the engine will now automatically drop into a fail-closed recovery routine attempting to forcibly `VirtualProtect` and rewrite the unmodified vanilla bytes. 
- If that recovery also fails (or memory readback doesn't match the vanilla pattern), it enters an unrecoverable `recoveryRequired = 1` conflict state.
- `patch*Ready` capability gates across the harness were upgraded. A mod feature is **never** considered dynamically safe unless: `record.installedByArchitect && record.savedOriginalValid && record.writeReadback && record.revertAvailability && !record.recoveryRequired && arch_bytes_equal(target, patchBytes)`.

**MSVC Compiler Dependency / Investigation**
Running under `/O2` revealed an aggressive Dead Store Elimination optimizer behavior in `cl.exe`. Because `memset(context, ...)` occurs immediately prior to the pointer offset calculation `ctxBase = context + (512 * 1024);`, the compiler unrolled `ctxBase` directly to `0` resulting in an immediate Access Violation `0xC0000005` precisely on the secondary RFLAGS loop iteration. 

Recompiling under `/Od` masked this behavior, establishing a strong `HARNESS_OPTIMIZATION_DEPENDENCY`. Re-evaluating the allocation with `volatile uint64_t ctxBase` successfully erected a compiler barrier, preserving `/O2` speeds while preventing execution drops. It's fully fixed without removing protections.
